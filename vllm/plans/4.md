## 问题定位

**问题有两层：**

### 1. vLLM 侧：`num_release_cpu_blocks` 没有注册为 CLI 参数

`num_release_cpu_blocks` 虽然在 `CacheConfig` 数据类中定义了字段，但 **缺少以下三处注册**：

| 位置 | 文件 | 说明 |
|------|------|------|
| `EngineArgs` 数据类 | `vllm/engine/arg_utils.py` ~L570 | 缺少 `num_release_cpu_blocks: int \| None = CacheConfig.num_release_cpu_blocks` |
| `add_cli_args()` 方法 | `vllm/engine/arg_utils.py` ~L926 | 缺少 `cache_group.add_argument("--num-release-cpu-blocks", ...)` |
| `create_engine_config()` | `vllm/engine/arg_utils.py` ~L1377 | 缺少 `num_release_cpu_blocks=self.num_release_cpu_blocks` 传入 `CacheConfig()` |

这就是 `--num-release-cpu-blocks 1000` 不被识别的根本原因。

### 2. vllm-ascend 侧：NPUWorker 缺少 release offload 适配

vLLM 的 `gpu_worker.py` 中新增了三个方法：
- `_init_release_cpu_caches()` — 分配 CPU pinned memory
- `offload_release_blocks()` — GPU→CPU 数据拷贝
- `load_release_blocks()` — CPU→GPU 数据拷贝

这些方法使用 `vllm._custom_ops.swap_blocks`（CUDA kernel），而 vllm-ascend 的 `NPUWorker` 是独立实现的（继承自 `WorkerBase`，不继承 `gpu_worker`），**不会自动获得这些方法**。

vllm-ascend 已有自己的 `swap_blocks` 实现（`torch.ops._C_ascend.swap_blocks`），用于 `CpuNpuOffloadingHandler` 中。需要在 `NPUWorker` 中添加对应的三个方法，使用 NPU 的 swap_blocks 算子。

## 适配方案

需要修改 **4 个文件**（3 个在 vLLM 侧，1 个在 vllm-ascend 侧）：

**vLLM 侧** — `vllm/engine/arg_utils.py`：
1. `EngineArgs` 类中添加 `num_release_cpu_blocks` 字段
2. `add_cli_args()` 中注册 `--num-release-cpu-blocks` 参数
3. `create_engine_config()` 中将字段传入 `CacheConfig()`

**vllm-ascend 侧** — `vllm_ascend/worker/worker.py`：
4. `NPUWorker` 中添加 `_init_release_cpu_caches()`、`offload_release_blocks()`、`load_release_blocks()` 三个方法，使用 `torch.ops._C_ascend.swap_blocks` 代替 `vllm._custom_ops.swap_blocks`，并在 `initialize_from_config()` 末尾调用 `_init_release_cpu_caches()`
