这个 commit 将 `jiuwen_vllm_affinity` 的 KV cache 插件合并到 vLLM 主代码中，实现了**跨请求的 KV cache 共享和显式释放**功能。以下是核心内容：

## 架构概览

整个功能分为 3 层：**API 层** → **引擎层** → **KV Cache 管理层**

### 1. API 层（入口）

- **`ChatCompletionRequest`** 新增 `cache_sharing: bool` 字段，开启后会用 `cache_salt` 标识共享 session
- **新增 `/release_kv_cache` POST 端点**（`ReleaseKvCacheRequest`），允许客户端显式释放某个 session 的部分 KV cache，通过 `messages_released_index` / `tools_released_index` 指定释放到第几条消息

### 2. 引擎层（传递机制）

- **`sharing_cache_salt` 打包进 `request_id`**：用 JSON 将 `request_id` 和 `sharing_cache_salt` 序列化在一起，通过 `pack_request_sharing_cache_salt` / `unpack_sharing_cache_salt` 编解码，利用现有 request_id 通道跨层传播 session 信息
- **`release_kv_cache` 方法**贯穿 `async_llm` → `core_client` → `EngineCore` → `Scheduler` → `KVCacheManager`
- `EngineCore.release_kv_cache` 将序列化的请求反序列化为 `Request`，计算 `block_hashes`，再按 token 比例算出要释放的 block 范围

### 3. KV Cache 管理层（核心）

- **`TwoPhaseBlockQueue`**（新文件，245 行）：替换原有的 `FreeKVCacheBlockQueue`，在双向链表基础上增加了 **aging 指针**。被释放的 block 不直接回到队列头部，而是通过 `aging_block()` 插入到 aging 指针位置，实现优先淘汰已释放 block 的策略
- **`KvCacheSessionManager`**（新文件，59 行）：维护 `block_to_sessions` 映射，实现 per-block 的 session 引用计数：
  - `add_blocks`：block 被某 session 命中时增加引用
  - `reset_blocks`：新分配 block 时重置为单 session
  - `release_blocks`：移除 session 引用，当引用归零时返回可 aging 的 block 列表
- **`SingleTypeKVCacheManager`** 集成了 session manager，在 `allocate_new_blocks_with_session` 和 `save_new_computed_blocks_with_session` 中维护 session 引用

### 数据流总结

```
请求到达 (cache_sharing=true, cache_salt="abc")
  → serving_chat: 把 cache_salt 打包进 request_id
  → Request.from_engine_core_request: 解包 sharing_cache_salt
  → KVCacheManager: 分配/复用 block 时记录 session 引用
  
释放请求 (/release_kv_cache)
  → serving_chat.release_kv_cache: 计算释放的 token 范围
  → EngineCore: 反序列化请求，算出 block_hash 范围
  → Scheduler → KVCacheManager → SessionManager: 移除 session 引用
  → 引用归零的 block 通过 aging_block() 被优先淘汰
```

核心思路是：同一个 `cache_salt` 的多个请求可以复用同一批 KV cache block，通过引用计数管理生命周期，释放时不立即回收而是进入 aging 区优先被淘汰。
